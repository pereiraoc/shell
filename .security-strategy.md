# Nova Estratégia de Segurança - Auto-Desabilitação Inteligente

**Data**: 2026-01-19  
**Versão**: 0.1.0-alpha (atualização)

---

## 🎯 Mudança Principal

### Antes (Rate Limiting + Lockout Temporal)
```
Tentativas falhas → Delay progressivo → Lockout temporal
                     (2s, 4s, 8s...)     (30s countdown)
```

**Problema**:
- ❌ User fica esperando countdown frustrante
- ❌ Não diferencia entre métodos
- ❌ Bloqueia todos métodos simultaneamente

### Agora (Auto-Desabilitação por Método)
```
Face: 5 falhas → Desabilita Face → PIN/Senha disponíveis
PIN: 10 falhas → Desabilita PIN → Face/Senha disponíveis  
Senha: 30 falhas → Lockout total → Apenas TTY

Unlock bem-sucedido → Todos métodos reativam
```

**Vantagens**:
- ✅ Sem countdown/espera temporal
- ✅ Sempre mantém alternativas disponíveis
- ✅ User aprende a usar métodos alternativos
- ✅ Protege contra brute force (limita tentativas)
- ✅ Reativação automática após unlock

## 📊 Comparação Detalhada

| Aspecto | Sistema Antigo | Sistema Novo |
|---------|----------------|--------------|
| **Face falha 5x** | Lockout 30s (todos métodos) | Face disabled, PIN/Senha OK |
| **PIN falha 10x** | Lockout 30s (todos métodos) | PIN disabled, Face/Senha OK |
| **User Experience** | Frustrante (countdown) | Fluido (tenta outro método) |
| **Brute Force** | Delay progressivo | Limite de tentativas por método |
| **Reativação** | Automática após timeout | Após unlock bem-sucedido |
| **Lockout Total** | Após N tentativas qualquer método | Apenas após 30 falhas na senha |

## 🔐 Regras de Segurança

### Face Authentication
- **Limite**: 5 tentativas
- **Ação**: Desabilita Face (botão grayed out)
- **Reativação**: Unlock via PIN ou Senha
- **Razão**: Limita tentativas de photo spoofing

### PIN Authentication
- **Limite**: 10 tentativas
- **Ação**: Desabilita PIN (botão grayed out)
- **Reativação**: Unlock via Face ou Senha
- **Razão**: Limita brute force (10/10000 = 0.1% de cobertura para PIN 4 dígitos)

### Password (Senha Tradicional)
- **Limite**: 30 tentativas
- **Ação**: Lockout total (todos métodos bloqueados)
- **Reativação**: Login via TTY (Ctrl+Alt+F2)
- **Razão**: Último recurso. Lockout apenas em abuso extremo.

## 💡 Cenários de Uso

### Cenário 1: Face Falha em Ambiente Escuro
```
1. User tenta Face → Fail (pouca luz)
2. Tenta novamente → Fail
3. ...
4. Após 5 tentativas → Face disabled

UI mostra: [Face (disabled)] [PIN] [Password]

5. User clica em PIN
6. Digita PIN correto → Unlock
7. Todos métodos reativam

Próxima sessão: [Face] [PIN] [Password]
                  ↑ reativado
```

**Vantagem**: User aprende que PIN funciona melhor em ambientes escuros.

### Cenário 2: Criança Tentando Desbloquear
```
1. Criança tenta Face 5x → Face disabled
2. Tenta PIN 10x (aleatório) → PIN disabled

UI mostra: [Face (disabled)] [PIN (disabled)] [Password]

3. Apenas senha disponível
4. Criança não sabe a senha → Desiste

5. Owner volta, digita senha → Unlock
6. Todos métodos reativam
```

**Vantagem**: Protege contra tentativas não autorizadas sem bloquear owner permanentemente.

### Cenário 3: Brute Force Attack
```
Atacante tenta brute force PIN 4 dígitos (10.000 combinações)

1. Tenta 10 PINs diferentes → PIN disabled
2. Face não reconhece atacante → Após 5 tentativas, Face disabled
3. Apenas senha disponível
4. Atacante não sabe senha → Bloqueado

Máximo de tentativas: 5 (Face) + 10 (PIN) + 30 (Senha) = 45 tentativas totais
```

**Vantagem**: Limita severamente tentativas de brute force.

## 📝 Implementação Técnica

### AuthState Manager
```qml
QtObject {
    id: authState
    
    // Contadores
    property int faceFailedAttempts: 0
    property int pinFailedAttempts: 0
    property int passwordFailedAttempts: 0
    
    // Estados
    property bool faceEnabled: Config.lock.auth.enableFaceAuth
    property bool pinEnabled: Config.lock.auth.enablePinAuth
    property bool passwordEnabled: true
    
    // Handlers
    function onFaceAuthFailed() {
        faceFailedAttempts++
        if (faceFailedAttempts >= Config.lock.auth.maxFaceRetries) {
            faceEnabled = false
        }
    }
    
    function onPinAuthFailed() {
        pinFailedAttempts++
        if (pinFailedAttempts >= Config.lock.auth.maxPinRetries) {
            pinEnabled = false
        }
    }
    
    function onPasswordAuthFailed() {
        passwordFailedAttempts++
        if (passwordFailedAttempts >= Config.lock.auth.maxPasswordRetries) {
            passwordEnabled = false
            // Lockout total
        }
    }
    
    function onUnlockSuccess() {
        // Reativa todos os métodos
        faceFailedAttempts = 0
        pinFailedAttempts = 0
        passwordFailedAttempts = 0
        
        faceEnabled = Config.lock.auth.enableFaceAuth
        pinEnabled = Config.lock.auth.enablePinAuth
        passwordEnabled = true
    }
}
```

### Config Padrão
```json
{
  "lock": {
    "auth": {
      "enableFaceAuth": true,
      "enablePinAuth": true,
      "defaultMethod": "face",
      "maxFaceRetries": 5,
      "maxPinRetries": 10,
      "maxPasswordRetries": 30
    }
  }
}
```

## ✅ Vantagens do Novo Sistema

### 1. User Experience
- ✅ Sem espera frustrante
- ✅ Feedback claro (botão disabled)
- ✅ Aprende a usar métodos alternativos
- ✅ Sempre tem uma opção disponível

### 2. Segurança
- ✅ Limita brute force (45 tentativas max antes de lockout total)
- ✅ Protege contra photo spoofing (5 tentativas Face)
- ✅ Protege contra PIN guessing (10 tentativas PIN)
- ✅ Último recurso sempre disponível (Senha)

### 3. Manutenção
- ✅ Sem timers para gerenciar
- ✅ Lógica simples (contador + flag)
- ✅ Estado claro (enabled/disabled)
- ✅ Fácil de testar

### 4. Flexibilidade
- ✅ Configurável por método
- ✅ User pode escolher método preferido
- ✅ Adapta-se ao ambiente (escuro → PIN, claro → Face)

## 🎯 Princípios de Design

1. **Conveniência sem comprometer segurança**
2. **Feedback claro e imediato**
3. **Sempre manter escape hatch (TTY)**
4. **Aprender com falhas (usa método alternativo)**
5. **Não punir excessivamente user legítimo**

## 📊 Comparação com Outros Sistemas

### Android
- **Estratégia**: Rate limiting temporal
- **5 falhas**: Espera 30s
- **10 falhas**: Espera 1min
- **15 falhas**: Espera 5min
- **❌ Problema**: Frustrante quando legítimo esquece PIN

### iOS
- **Estratégia**: Rate limiting + wipe
- **6 falhas**: Disabled 1min
- **10 falhas**: Wipe device (se configurado)
- **❌ Problema**: Muito agressivo, pode perder dados

### Windows Hello
- **Estratégia**: Fallback para PIN/Password
- **Face falha 3x**: Pede PIN
- **✅ Similar ao nosso sistema**

### Este Sistema
- **Estratégia**: Auto-desabilitação individual + reativação automática
- **✅ Sem countdown frustrante**
- **✅ Sempre mantém alternativas**
- **✅ Protege contra brute force**
- **✅ Aprende com uso**
